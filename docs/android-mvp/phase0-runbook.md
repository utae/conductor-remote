# 단계 0 시험 절차서 — Conductor 연결 검증

[PRD](./prd.md) §12 단계 0의 실행 절차. 목적은 **원본 `conductor-remote` 그대로**(코드 변경 없음)
Galaxy에서 Mac의 기존 Conductor 대화에 지시를 보내고, 같은 대화에 남는지 확인하는 것이다.
Claude·Codex 양쪽이 핵심 기준을 통과하기 전에는 UI 신규 개발에 들어가지 않는다.

> [!IMPORTANT]
> 전송 시험은 Mac의 Conductor 창을 실제로 조작한다(Accessibility). 시험하는 동안 Mac에서 손대지 않고,
> **시험 한 건마다 시작 전에 확인**한다. 사람의 클릭이 겹치면 실패하며 이는 결함이 아니라 경합이다.
> 개인 호스트명·토큰·대화 내용은 결과 기록에 적지 않는다.

## 0. 준비

| 항목 | 확인 방법 |
|---|---|
| Mac이 깨어 있고 잠금 해제 | 시험 시작 전 화면 확인 |
| Conductor 실행·창 1개 이상 | Conductor 창이 보이는지 |
| 릴레이 설치 | `pnpm service status` |
| 노출 모드가 **tailnet** | `pnpm service status`가 "tailnet-only"를 표시. `public`이면 `--expose tailnet`(또는 `EXPOSE=tailnet`)로 다시 배포. 배포는 사용자가 직접 한다 |
| Galaxy에 Tailscale 설치·같은 tailnet 로그인 | Tailscale 앱에서 Mac이 보이는지 |
| Galaxy Chrome에서 PWA 설치 | 상태 URL을 열고 "홈 화면에 추가" |

시험용 대화 두 개를 Mac에서 미리 만든다(실작업 대화를 쓰지 않는다).

- Claude Code 대화 1개, Codex 대화 1개. 각각 별도 워크스페이스.
- 승인된 시험 지시문 예: `시험입니다. "ok-<번호>" 한 줄로만 답하세요.` 번호는 시험마다 다르게.

## 1. 기록 양식

시험마다 한 줄씩 `docs/android-mvp/results/<날짜>.md`에 남긴다.

```
- 항목 / 에이전트(Claude|Codex) / 결과(통과|실패|보류) / 관찰 / Conductor 버전 / 기기
```

## 2. 항목별 절차 (PRD §11)

각 항목은 Claude, Codex 모두 수행한다. `[UI]`는 Mac의 Conductor 창을 조작하므로 **실행 전 확인** 대상.

| # | 항목 | 절차 | 통과 기준 |
|---|---|---|---|
| 1 | 전송 | `[UI]` 폰에서 시험 지시 1건 전송. Mac에서 같은 대화를 확인 | 지시와 응답이 Mac의 같은 대화에 순서대로 남음 |
| 2 | 대상 정확성 | `[UI]` Mac에서 다른 대화·다른 워크스페이스를 열어 둔 채 폰으로 전송 | 지정한 대화에만 도착, 다른 대화 변화 없음 |
| 3 | 중복 방지 | `[UI]` 전송 버튼 연속 탭, 전송 직후 앱 강제 종료·재실행, 전송 중 네트워크 전환 | 대화에 사용자 메시지가 **정확히 1건** |
| 4 | 접수 표시 | 폰 화면의 전송 상태 전이를 녹화 | Conductor에 행이 생기기 전 "완료"로 보이지 않음 |
| 5 | 기록 일치 | 시험 후 폰과 Mac의 마지막 3턴을 비교 | 사용자 지시·최종 응답의 순서·내용 일치 |
| 6 | 잠금 | Mac 화면을 잠그고 `[UI]` 폰으로 전송 → 잠금 해제 | 전송 대기로 표시, 해제 후 1회만 도착, 임의 재전송 없음 |
| 7 | 오프라인 | 폰을 비행기 모드로 두고 전송 시도 → 복구 | 전송되지 않았음 또는 확인 필요로 표시, 자동 재전송 없음 |
| 8 | 작업 보존 | 목록·대화 새로고침을 반복하고 `git status`, 세션 수를 전후 비교 | 기존 세션·worktree 변화 없음 |
| 9 | 아카이브 | 아카이브된 워크스페이스와 폴더가 없는 작업을 목록에서 확인 | 활성 작업으로 오인되지 않음 |
| 10 | 접근 통제 | 토큰 없이 `/api/state` 호출, 토큰 교체 후 옛 토큰으로 호출 | 401. 현재 원본은 기기별 철회가 없으므로 "토큰 교체=전체 철회"로 기록 |

성능은 정상 연결에서 목록·대화 최초 표시 3초, 새 기록 반영 5초를 실기기에서 3회 측정해 중앙값을 적는다.
모델 응답 생성 시간은 제외한다.

## 3. 판정과 다음 단계

- **Claude·Codex 모두 1~5 통과**: 단계 1로 진행.
- 한쪽이라도 1~3 실패: 원인(Conductor 버전 변화, Accessibility 권한, 에이전트별 UI 차이)을 분리해 기록하고 UI 개발을 시작하지 않는다.
- 6~10의 실패는 단계 2~3의 작업 항목으로 이관한다(PR 계획 참조).
- 알려진 제약: 덮개를 닫으면 키프어웨이를 켜도 약 16초 뒤 세션이 잠긴다. 6번 결과가 곧 지원 범위의 기준이다.
