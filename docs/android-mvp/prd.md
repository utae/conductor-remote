# PRD: Conductor용 Android 원격 클라이언트

버전: 0.1 · 초안  
작성일: 2026-10-23  
제품명: 미정

## 1. 제품 목표

Galaxy에서 Mac의 Conductor 로컬 워크스페이스를 조회하고, 기존 대화에 지시를 보내며, 결과를 확인한다.

**휴대폰에서 보낸 지시와 에이전트 응답은 Mac Conductor의 동일한 대화에 남아야 한다.**

## 2. 해결할 문제

현재 Sesori는 Claude·Codex 기록을 가져와 조회하고 세션을 이어갈 수 있지만, Sesori에서 진행한 대화가 Conductor 자체 대화 기록에 반영되지 않는 문제가 확인됐다.

사용자는 다음을 원한다.

- 외부에서도 Galaxy로 진행 상황 확인.
- Mac에서 시작한 Conductor 대화에 후속 지시 전송.
- Mac으로 돌아왔을 때 휴대폰에서 진행한 대화를 그대로 확인.
- 활성 작업과 아카이브된 작업을 명확히 구분.

## 3. 대상 사용자와 사용 환경

초기 대상은 Galaxy Android와 개인 Mac에서 Conductor를 사용하는 단일 사용자다.

- 에이전트: Claude Code, Codex.
- 실행 환경: Mac의 기존 Conductor 로컬 워크스페이스.
- 접속 환경: 같은 Wi-Fi 및 외부 모바일 네트워크.
- 전제 조건: Mac이 켜져 있고, 깨어 있으며, 인터넷에 연결되고 Conductor가 실행 중이어야 한다.

클라우드 워크스페이스와 다중 사용자 협업은 초기 범위에서 제외한다.

## 4. 핵심 사용자 흐름

### 최초 연결

1. Mac에 Bridge를 설치한다.
2. 필요한 연결·권한 상태를 확인한다.
3. Android 앱에서 QR 코드 등으로 Mac을 등록한다.
4. 연결 성공 후 기존 Conductor 워크스페이스 목록을 표시한다.

### 기존 작업 이어가기

1. 프로젝트와 워크스페이스를 선택한다.
2. 해당 워크스페이스의 기존 대화를 연다.
3. 최근 지시·응답과 에이전트 상태를 확인한다.
4. 후속 지시를 보낸다.
5. Conductor가 지시를 접수했는지 확인한다.
6. 응답을 조회하고 Mac의 같은 대화에서도 확인한다.

### 연결 실패 후 복구

1. 전송 상태가 불확실하면 이를 표시한다.
2. 재연결 후 Conductor 기록과 전송 결과를 대조한다.
3. 접수 여부를 확인하기 전에는 같은 지시를 자동 재전송하지 않는다.

## 5. MVP 기능 요구사항

| ID | 기능 | 요구사항 |
|---|---|---|
| F1 | Mac 등록 | 연결 정보 안전 저장, 연결 해제 및 접근 철회 지원 |
| F2 | 연결 상태 | Bridge 연결, Conductor 실행, 전송 가능 여부를 구분 |
| F3 | 작업 목록 | 프로젝트·워크스페이스·대화 목록과 검색 제공 |
| F4 | 기존 대화 조회 | 사용자 메시지, 에이전트 응답, 코드 블록, 도구 실행 요약 표시 |
| F5 | 지시 전송 | 선택한 Conductor 대화에 텍스트 지시 전송 |
| F6 | 접수 확인 | Conductor에 저장된 사실을 확인한 후 접수 완료 표시 |
| F7 | 진행 상태 | 작업 중, 대기, 사용자 확인 필요, 오류 상태 표시 |
| F8 | 재연결 | 마지막 조회 위치를 기준으로 누락된 기록 가져오기 |
| F9 | 작업 분류 | 활성 작업 기본 표시, 아카이브는 별도 보기 |
| F10 | 경로 오류 | 폴더 없는 작업은 원인 표시 및 전송 차단 |

### 전송 상태

앱은 다음 상태를 구분한다.

- **전송 중:** Bridge에 요청 전달 중.
- **전송 대기:** Mac 잠금 등으로 아직 Conductor에 전달되지 않음.
- **접수 완료:** 대상 Conductor 대화에 메시지 저장 확인.
- **처리 중:** 에이전트 실행 확인.
- **실패:** 전달되지 않았음을 확인.
- **확인 필요:** 전달됐을 가능성이 있으나 접수 여부 확인 불가.

네트워크 요청 성공만으로 접수 완료를 표시하지 않는다.

## 6. 데이터 및 실행 원칙

### Conductor를 기준으로 동작

- 프로젝트·대화 목록은 Conductor 상태를 기준으로 한다.
- 지시는 Conductor의 메시지 전달 경로를 통해 보낸다.
- Bridge가 Claude·Codex를 별도로 실행하거나 `--resume`으로 대화를 이어가지 않는다.
- Conductor DB에 메시지를 직접 삽입해 동기화를 흉내 내지 않는다.
- 앱의 로컬 캐시는 갱신·삭제 가능한 조회용 사본으로 취급한다.

### 정확한 대화 지정

워크스페이스 이름이나 현재 열린 창만으로 대상을 추정하지 않는다. 워크스페이스 ID와 대화 ID를 확인하고, 대상이 맞는지 검증한 뒤 전송한다.

### 기존 작업 보존

- 목록 조회·새로고침으로 세션이나 Worktree를 변경하지 않는다.
- 폴더가 없다는 이유로 대화 기록을 자동 삭제하지 않는다.
- 아카이브·삭제 기능은 MVP에 포함하지 않는다.

## 7. UI 방향

Sesori의 간결한 프로젝트 목록과 모바일 채팅 흐름을 참고하되, 화면·아이콘·브랜드 자산은 새로 제작한다.

### 주요 화면

| 화면 | 주요 내용 |
|---|---|
| 연결 | Mac 등록, 연결 진단, 권한 안내 |
| 작업 목록 | 검색, 프로젝트별 작업, 상태, 최근 활동 |
| 대화 | 메시지 기록, 도구 실행 요약, 입력창, 전송 상태 |
| 설정 | 연결 관리, 테마, 진단 정보, 캐시 삭제 |

### 표현 원칙

- 전송 대상 워크스페이스·대화 이름을 입력창 주변에 항상 표시.
- 긴 도구 출력은 접고 필요한 경우 펼치기.
- 코드·경로 복사 지원.
- 한국어 우선, 시스템 글자 크기와 다크 모드 지원.
- 기술적 오류는 사용자가 취할 다음 행동과 함께 표시.
- 잠금·오프라인·대상 없음 상태를 같은 오류로 묶지 않는다.

## 8. 구현 방향

### 제안 구조

**Android 클라이언트 ↔ Mac Bridge ↔ Conductor ↔ Claude·Codex**

초기 기반은 `hyldmo/conductor-remote` 포크를 활용하는 방향으로 검토한다.

- 재사용 후보: Conductor 조회, 대화 대상 지정, 지시 전달, 대기열, 중복 방지, 접수 확인.
- 신규 개발: Sesori를 참고한 모바일 UI와 Android 연결·보안 저장 기능.
- 기존 웹 UI는 초기 호환성 검증 도구로 활용 가능.
- Android 구현 기술과 네이티브 앱·웹 기반 패키징 선택은 연결 검증 후 확정.

해당 프로젝트는 MIT 라이선스이며, 재사용 시 저작권·라이선스 고지를 유지한다.

### 접속 방식

초기 검증은 Tailscale 사설망을 사용한다. 공개 인터넷 노출은 기본값으로 사용하지 않는다.

최종 제품에서 Tailscale을 계속 필수로 할지, 자체 중계 서비스를 제공할지는 후속 결정한다.

## 9. 보안 요구사항

- 연결 자격 증명을 Android 보안 저장소에 보관.
- 인증 없는 조회·지시 전송 차단.
- 로그에 토큰·전체 대화·비밀값을 기본 기록하지 않음.
- Mac에서 휴대폰 접근 철회 가능.
- macOS 권한은 용도와 영향을 설명한 뒤 요청.
- 전송을 위해 화면 잠금이나 시스템 보안 설정을 임의로 해제하지 않음.
- 에이전트 권한을 자동 승인하는 기능은 MVP에서 제공하지 않음.

## 10. MVP 제외 범위

- 새 워크스페이스·새 대화 생성.
- 작업 중지, 권한 승인, Plan 승인.
- 모델·권한 모드 변경.
- 파일 첨부·음성 입력.
- PR 병합·워크스페이스 아카이브·기록 삭제.
- 다중 Mac·다중 사용자.
- 자체 클라우드 중계·계정 시스템.
- Play 스토어 공개 출시.

초기 배포는 개인 테스트용 Android 설치 파일을 목표로 한다. 후속 기능은 핵심 전송 검증 후 추가한다.

## 11. 검증 및 출시 기준

| 검증 항목 | 통과 기준 |
|---|---|
| Claude 전송 | 휴대폰 지시·응답이 Mac의 동일한 Conductor 대화에 남음 |
| Codex 전송 | Claude와 동일한 기준 충족 |
| 대상 정확성 | 대화 전환·여러 창 환경에서 다른 대화로 오전송 없음 |
| 중복 방지 | 연속 탭·타임아웃·재연결 시험에서 중복 실행 없음 |
| 접수 표시 | Conductor 저장 확인 전 접수 완료 표시 없음 |
| 기록 일치 | 앱과 Conductor에서 사용자 지시·최종 응답의 순서와 내용 일치 |
| 잠금·오프라인 | 상태를 정확히 표시하고, 불확실한 지시를 임의 재전송하지 않음 |
| 작업 보존 | 조회 과정에서 기존 세션·Worktree 변경 없음 |
| 아카이브 처리 | 폴더 없는 작업이 활성 작업으로 오인되지 않음 |
| 접근 통제 | 미등록 기기·철회된 자격 증명의 접근 차단 |

목표 성능은 정상 연결에서 목록·대화 최초 표시 3초 이내, 새 기록 반영 5초 이내로 두고 실제 기기에서 측정한다. 모델 응답 생성 시간은 제외한다.

## 12. 개발 단계

### 단계 0 — Conductor 연결 검증

현재 Mac과 Galaxy에서 원본 `conductor-remote`를 시험한다. 테스트용 대화에 승인된 지시를 보내고 Conductor 저장 여부를 확인한다.

**Claude·Codex 모두 핵심 기준을 통과하기 전 본격 UI 개발에 들어가지 않는다.**

### 단계 1 — 읽기 전용 모바일 화면

연결, 작업 목록, 검색, 대화 조회를 구현한다.

### 단계 2 — 안전한 지시 전송

대상 검증, 전송 상태, 중복 방지, 재연결 복구를 구현한다.

### 단계 3 — Android 개인 배포

설치·업데이트 흐름, 자격 증명 저장, 실제 Galaxy 사용성을 검증한다.

### 단계 4 — 후속 기능

알림, 승인·중지, 첨부, 다중 Mac 등을 사용 우선순위에 따라 추가한다.

## 13. 주요 위험과 미결정 사항

| 항목 | 대응·결정 방향 |
|---|---|
| Conductor 로컬 공개 API 부재 | 연결부를 격리하고 버전별 호환성 검사 제공 |
| UI 자동화·비공개 연결 변경 | 실패 시 전송을 중단하고 지원 상태 표시 |
| Mac 잠금 상태의 전송 제약 | 실제 시험 후 지원 범위 명시 |
| 원본 프로젝트 변경 반영 | 연결부 수정 최소화, 검증한 버전으로 고정 |
| Android 구현 기술 | 단계 0 통과 후 결정 |
| 비공개 개발 여부 | Public 포크 유지 또는 독립 Private 저장소 선택 |
| 기존 Sesori 사용 | 삭제·중단은 별도 결정하며 앱 개발과 자동 연계하지 않음 |

## 14. 성공의 정의

사용자가 Galaxy에서 기존 Conductor 대화에 지시를 보내고, 결과를 확인한 뒤 Mac으로 돌아왔을 때 **같은 대화 기록을 그대로 이어서 사용할 수 있다.**
